# 발리 신혼여행 계획 — 부부 공동 편집 앱

두 사람이 각자 휴대폰에서 같은 계획표를 고치면, 상대방 화면에 바로 나타납니다.
원래 쓰시던 `발리_신혼여행_계획.html` 의 **내용과 디자인은 그대로** 두고,
자동 저장과 실시간 동기화만 새로 넣었습니다.

- 앱 파일: `public/index.html`
- 보안 규칙: `firestore.rules`
- Netlify 설정: `netlify.toml`

---

## 1단계 · Firebase 프로젝트 만들기 (약 5분)

개발 지식 없이 화면에서 누르기만 하면 됩니다. 카드 등록 필요 없고, 두 사람이 쓰는
정도는 **무료 한도**(하루 읽기 5만 회 / 쓰기 2만 회) 안에서 넉넉히 해결됩니다.

### 1-1. 프로젝트 생성
1. <https://console.firebase.google.com> 에 접속해 구글 계정으로 로그인합니다.
2. **프로젝트 만들기** 를 누릅니다.
3. 프로젝트 이름에 `bali-honeymoon` 처럼 아무 이름이나 넣고 **계속**.
4. **Google 애널리틱스** 는 **사용 안 함** 으로 끄고 **프로젝트 만들기**.
5. "새 프로젝트가 준비되었습니다" 가 뜨면 **계속**.

### 1-2. 익명 로그인 켜기
계정을 따로 만들 필요 없이, 앱이 알아서 조용히 로그인하게 하는 기능입니다.

1. 왼쪽 메뉴에서 **빌드 → Authentication** → **시작하기**.
2. **Sign-in method(로그인 방법)** 탭을 누릅니다.
3. 목록 맨 아래 **익명(Anonymous)** 을 누릅니다.
4. **사용 설정** 토글을 켜고 **저장**.

> 이걸 켜지 않으면 앱 아래에 "익명 로그인을 켜주세요" 라고 안내가 뜹니다.

### 1-3. Firestore 데이터베이스 만들기
1. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기**.
2. 위치는 **asia-northeast3 (서울)** 을 고릅니다. (한국에서 제일 빠릅니다)
3. **프로덕션 모드에서 시작** 을 고르고 **만들기**.
   → 이 상태는 아무도 못 읽고 못 쓰는 상태입니다. 다음 단계에서 규칙을 넣습니다.

### 1-4. 보안 규칙 넣기
1. Firestore Database 화면 위쪽의 **규칙(Rules)** 탭을 누릅니다.
2. 편집창 안의 내용을 **전부 지우고**, 이 저장소의 **`firestore.rules` 파일 내용을
   통째로 복사해서 붙여넣습니다.**
3. **게시(Publish)** 를 누릅니다.

### 1-5. 설정값(apiKey 등) 복사하기
1. 왼쪽 위 **프로젝트 개요** 옆의 **톱니바퀴 ⚙️ → 프로젝트 설정**.
2. 아래로 내려 **내 앱** 에서 **웹 아이콘 `</>`** 을 누릅니다.
3. 앱 닉네임에 `bali-web` 을 넣고, **"Firebase 호스팅도 설정" 체크는 하지 않은 채**
   **앱 등록**.
4. 다음 화면에 이런 코드가 나옵니다. **이 부분을 통째로 복사**하세요.

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "bali-honeymoon-xxxx.firebaseapp.com",
  projectId: "bali-honeymoon-xxxx",
  storageBucket: "bali-honeymoon-xxxx.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef"
};
```

### 1-6. 앱에 붙여넣기 — ✅ 완료됨

`public/index.html` 의 `FIREBASE_CONFIG` 에 프로젝트 `mgsg-344be` 의 설정값이
이미 들어가 있습니다. 더 손대실 것 없습니다.

> **이 값들은 비밀번호가 아닙니다.** 원래 웹페이지에 그대로 공개되는 값이라
> 누가 봐도 괜찮습니다. 실제 잠금장치는 1-4단계의 **보안 규칙**과 **방 코드**입니다.
> (더 조이고 싶으시면 Google Cloud 콘솔에서 이 API 키에 HTTP 리퍼러 제한을 걸어
> Netlify 주소에서만 쓰이게 할 수 있습니다. 필수는 아닙니다.)

### 1-7. (권장) Netlify 주소를 허용 목록에 넣기
배포 후 주소를 알게 되면, Firebase 콘솔 **Authentication → Settings(설정) →
승인된 도메인** 에 Netlify 주소(예: `bali-plan.netlify.app`)를 **도메인 추가** 해
두세요. 익명 로그인 자체는 대개 이것 없이도 되지만, 넣어두면 나중에 생길 수 있는
문제를 미리 막아줍니다.

## 2단계 · Netlify 에 배포하기 (GitHub 연결 방식)

이 저장소에 코드가 이미 올라가 있으므로, 한 번만 연결해두면 앞으로는
**푸시할 때마다 자동으로 다시 배포**됩니다.

1. <https://app.netlify.com> 에 로그인합니다. (GitHub 계정으로 로그인하면 편합니다)
2. **Add new site → Import an existing project**.
3. **Deploy with GitHub** 를 고르고, 권한 요청이 뜨면 승인합니다.
4. 저장소 목록에서 **`moonmingyu-d/-_-`** 를 고릅니다.
   - 목록에 없으면 **Configure the Netlify app on GitHub** 에서 이 저장소를 허용해 주세요.
5. 브랜치는 `main`(또는 이 작업 브랜치), 나머지 빌드 설정은 **손대지 않아도 됩니다.**
   `netlify.toml` 에 이미 적어두었습니다.
   - Publish directory: `public`
   - Build command: 없음 (정적 사이트)
6. **Deploy site** 를 누르면 1분 안에 `https://무작위이름.netlify.app` 주소가 나옵니다.
7. **Site configuration → Change site name** 에서 `bali-mingyu-sojeong` 처럼
   기억하기 쉬운 이름으로 바꿔두면 좋습니다.
8. 주소가 정해지면 **1-7단계**(승인된 도메인 추가)를 해주세요.

## 3단계 · 둘이서 쓰기

1. 배포된 주소를 휴대폰에서 엽니다.
2. **새 방 만들기** 를 누르면 `bali-7k4m-9qxt-3rvd` 같은 코드가 만들어집니다.
3. **링크 복사** 를 눌러 나온 링크를 **배우자에게 한 번만** 보냅니다.
   (단톡방 말고 둘만 있는 대화방으로 보내주세요 — 이 링크가 곧 열쇠입니다.)
4. 배우자가 그 링크를 열면 같은 계획이 뜨고, 이제부터 서로 고친 게 바로 보입니다.
5. 아이폰 Safari 는 **공유 → 홈 화면에 추가**, 안드로이드 Chrome 은
   **⋮ → 홈 화면에 추가** 를 하면 앱처럼 쓸 수 있습니다.

### 화면 아래 표시 읽는 법

| 표시 | 뜻 |
|---|---|
| 🟢 연결됨 · 자동 저장 | 정상. 고치는 즉시 저장되고 상대방에게 갑니다 |
| 🟡 저장 중… | 방금 고친 내용을 보내는 중 |
| 🔴 연결 끊김 — 다시 연결 중 | 인터넷이 끊긴 상태. **고쳐도 안 날아갑니다.** 연결되면 알아서 보냅니다 |

그 아랫줄에는 마지막으로 누가 언제 고쳤는지와 방 코드가 나옵니다.

### 버튼

- **내용 복사** — 지금 계획 전체를 글자로 복사 (카톡·메모장에 백업용)
- **붙여넣기** — 복사해 둔 내용으로 되돌리기 (양쪽 모두 바뀝니다)
- **다시 연결** — 연결이 끊겼을 때만 나타납니다
- **방 코드** — 방 코드 확인·변경
- **처음** — 맨 처음 계획으로 되돌리기 (양쪽 모두 바뀝니다)

## 보안 규칙이 하는 일

`firestore.rules` 를 사람 말로 옮기면 이렇습니다.

1. **로그인하지 않은 사람은 아무것도 못 합니다.** (익명이라도 로그인은 해야 합니다)
2. **방 코드가 곧 비밀번호입니다.** 그래서 12자보다 짧은 코드는 아예 만들지 못하게
   막았습니다. 앱이 만들어주는 코드는 19자에 조합이 약 10¹⁸ 가지라
   찍어서 맞히는 건 사실상 불가능합니다.
3. **이 앱이 쓰는 모양의 문서만** 저장됩니다. 엉뚱한 항목이나 지나치게 큰 데이터는
   거부합니다.
4. **삭제는 아무도 못 합니다.** 사고로 계획이 통째로 날아가지 않습니다.
5. `rooms` 말고 **다른 경로는 전부 막혀** 있습니다.

이 규칙 12가지를 실제 서버에 요청을 보내 하나씩 확인해 두었습니다 (`npm run test:rules`).

**남는 위험 한 가지:** 방 코드(또는 링크)를 다른 사람이 알게 되면 그 사람도 계획을
볼 수 있습니다. 링크는 둘만 있는 대화방으로 보내주세요.
혹시 유출된 것 같으면 **방 코드** 버튼으로 새 방을 만들고, 옮기기 전에 **내용 복사**
→ 새 방에서 **붙여넣기** 하면 됩니다.

## 개발자용 메모

```bash
npm install
npm run build:vendor    # Firebase SDK 를 public/vendor/firebase.js 로 묶기
npm run emulators       # 로컬 Firebase 에뮬레이터 (Java 필요)
npm run test:rules      # 보안 규칙 12가지 검증
npm run test:sync       # 브라우저 창 2개로 실시간 동기화 13가지 검증 (에뮬레이터)
LIVE=1 npm run test:sync   # 같은 검증을 실제 Firebase 프로젝트로 (인터넷 직결 필요)
npm run verify:live     # 실제 프로젝트의 로그인·규칙·저장·읽기 확인
```

### 어떻게 동작하나

- 계획 전체가 Firestore 문서 하나(`rooms/{방코드}`)에 들어갑니다.
- 다만 한 덩어리가 아니라 **섹션별로 나눠 담습니다**
  (`bookings` `days` `resorts` `budget` `checklist` `tips` `cap`).
  그리고 **내가 실제로 바꾼 섹션만 골라서** 보냅니다.
  덕분에 남편이 예산을, 아내가 일정을 동시에 고쳐도 서로를 덮어쓰지 않습니다.
- 상대방 수정이 도착하면 **달라진 섹션만** 다시 그립니다.
  내가 글자를 쓰고 있던 칸은 다시 그린 뒤 **원래 글자와 커서 위치까지 되돌려 놓습니다.**
- 오프라인은 Firestore 의 로컬 캐시(IndexedDB)가 처리합니다.
  끊긴 동안 고친 내용은 쌓여 있다가 연결되면 자동으로 올라갑니다.
  추가 안전망으로 `localStorage` 에도 사본을 남깁니다.
- Firebase SDK 는 CDN 대신 `public/vendor/firebase.js` 로 함께 배포합니다.
  외부 CDN 사정과 무관하게 항상 뜹니다.

## 잘 안 될 때

앱 아래쪽 상태줄에 원인이 그대로 나옵니다. 자주 나오는 두 가지입니다.

| 증상 | 원인 | 해결 |
|---|---|---|
| "Firebase 콘솔 → Authentication → 로그인 방법에서 익명을 켜주세요" | Authentication을 아직 시작하지 않았거나 익명 로그인이 꺼져 있음 | **1-2단계** |
| "이 방을 열 권한이 없어요" / "저장 거부됨" | Firestore를 안 만들었거나 보안 규칙을 안 붙여넣음 | **1-3, 1-4단계** |

설정이 제대로 됐는지 한 번에 확인하려면:

```bash
npm run verify:live
```

실제 프로젝트에 붙어서 익명 로그인·보안 규칙·저장·읽기를 하나씩 검사하고,
안 되는 항목은 이유를 알려줍니다.
